\section{Conclusion}\label{sec:conclusion}

This project addressed a concrete weakness in Interhyp's internal multi-agent chatbot: routing errors had previously been identified through user reports and corrected through case-by-case analysis and manual prompt refinement. The objective was therefore to design, implement, and evaluate a reproducible pipeline that could assess routing decisions, derive an improvement signal, and demonstrate measurable gains across accuracy, latency, and cost. Within the defined scope of a self-contained showcase rather than a production integration into Robin, this objective was achieved.

The resulting artifact is an end-to-end system rather than an isolated optimization experiment. Its Router combines a selective similarity-based first stage with an LLM-based second stage. An LLM judge supplies structured feedback to an OPRO-based optimizer, which proposes improved Stage 2 prompts. PropDesk makes this process observable: its dashboards support training, compare prompt versions on fixed evaluation data, expose the optimization trajectory, and prepare operational metrics for live use. Prompt versioning, deployment controls, separated training and evaluation data, and the accompanying handover material make the workflow reproducible and transferable to Interhyp.

Compared with the initial requirements, the final implementation covers all three performance dimensions agreed during Sprint 0. Controlled evaluation and prompt optimization address accuracy, while Stage 1 addresses latency and model use by accepting sufficiently confident similarity-based decisions and escalating the remainder. Avoiding Stage 2 calls also provides a mechanism for reducing variable model costs, although exact production savings could not be measured without live traffic. The dashboards and versioned records make improvements comparable instead of accepting a revised prompt solely because it appears plausible.

The controlled Stage 2 experiment provides the clearest evidence for the effect of prompt optimization. With Stage 1 disabled, the original prompt correctly routed 200 of the fixed 240 evaluation queries, corresponding to 83\% accuracy. Its errors were not distributed randomly, with the most notable failure being its inability to select the \texttt{PlatformSupportAgent} for any of its assigned queries. The optimized prompt routed all 240 evaluation queries correctly and therefore reached 100\% accuracy, an improvement of 17 percentage points. Because the optimizer used a separate 1,000-query training set, the evaluation set remained fixed and unseen, and Stage 1 write-back was disabled during this experiment, the measured change can be attributed to the revised Stage 2 prompt within the synthetic showcase setting. The result demonstrates that judge-derived feedback can expose systematic weaknesses in agent boundaries and support prompt revisions that generalize beyond the cases used to generate the feedback.

Restoring the complete two-stage Router introduced an explicit accuracy--efficiency trade-off. The final configuration routed 235 of 240 queries correctly and reached 98\% accuracy. Stage 1 resolved 188 queries directly, covering 78\% of the evaluation set and avoiding the same number of Stage 2 LLM calls. Average latency decreased from 669 ms for the original Stage 2-only baseline to 407 ms, a reduction of 262 ms or 39\%. The complete Router consequently retained most of the accuracy improvement while using the LLM selectively. Its two-percentage-point difference from the optimized Stage 2-only result is the cost of the chosen operating point, rather than evidence that prompt optimization became less effective. This distinction is important: the Stage 2 experiment isolates the benefit of optimization, whereas the full configuration demonstrates how that benefit can be combined with lower latency and model use.

The project also clarifies what self-improvement means in this context. The system does not treat every automated verdict as ground truth or deploy every generated prompt. Instead, routing runs produce evidence, the judge converts failures into a structured signal, the optimizer proposes alternatives, and candidates are evaluated before deployment. The difference between the two available signals shows why these controls matter. On the final 1,000-query training run, the strongest prompt reached 99\% accuracy against the predefined golden labels but 94\% according to the judge-derived evaluation. The golden label checks the assigned agent, whereas the judge compares generated answers from a Router-dependent candidate pair. The judge was therefore useful for ranking candidates and steering optimization, but its reported accuracy is not a calibrated substitute for independent labels.

The conclusions remain bounded by the project conditions. All experiments relied on synthetic queries in a structurally comparable real-estate scenario, the improvement loop used a single judge, and only a limited set of models and configurations was tested. The measured latency also reflects the showcase infrastructure. The results establish technical feasibility, not Robin's expected performance under live broker traffic. The next step should be validation on independently labelled production samples, followed by monitoring of accuracy, latency, Stage 1 coverage, and cost. Periodic human audits should calibrate the judge, while deteriorating reliability could justify targeted human review or a diverse judge panel. With these safeguards, the project provides Interhyp with more than a successful prototype: it establishes a practical foundation for replacing ad hoc Router refinement with a versioned, inspectable, and evidence-based improvement process.
